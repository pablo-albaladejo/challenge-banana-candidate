# knowledge

## Purpose

The bank's document corpus as searchable knowledge: ingestion (read the corpus in `fixtures/documents/`, chunk, embed), the SQLite-backed vector store, semantic search with a lexical (FTS5/BM25) fallback, the `search_documents` agent tool and the `documents`, `search` and `ingestion` endpoints.

Hexagonal vertical (plan §10, 7d.1): `domain/` (pure rules), `application/` (ports, use cases; no services), `infrastructure/` (adapters), `entry-points/` (wiring, tools, http, the frozen legacy surface). Nothing else lives at the root but `index.ts` and this file.

## For AI Agents

### Working In This Directory

- Index lives in app DB tables `chunks`, `embedding_cache`, `meta` (not the bank DB). `infrastructure/{sqlite-chunk-store,cached-openai-embedder,sqlite-lexical-index}.ts` (the last owns the lazily built `chunks_fts`, not in the seed wipe list: it rebuilds itself) are the only owners of that SQL. Callers: `../assistant/entry-points/dependencies.ts` (the `KnowledgePort`: `knowledge().searchDocuments({ query, role: 'customer' })`), the tool, the `http/` handlers, `../server/seed.ts` (`documents` and `restoreIndex` from the index; `restoreIndex` is re-exported through `entry-points/legacy.ts`), `scripts/ingest.ts` (index) and `scripts/doctor.ts` (`embedTexts`).
- Triggered by `npm run ingest` / `npm run setup` (scripts in `scripts/`); the seed can instead restore the committed index without calling OpenAI. Ingest is a full replace in one transaction (`replaceChunks`); embeddings are cached in `embedding_cache` by model+dimensions+text.
- Vectors are assumed normalized, so dot product = cosine; there is no ANN index (full scan on every query).
- Lint (`eslint.config.mjs`): knowledge is a layered vertical, so `index.ts` re-exports only `./entry-points/` (type-only re-exports are allowed: `allowTypeImports`), and `src/server/` reaches it only through the index, `seed.ts` included (`../knowledge/index` is accepted too).
- Things worth scrutinizing:
  - Search filters by audience and by validity on `referenceDate`, but has no minimum score, so weak matches are still returned; superseded versions are all indexed and only filtered at query time.
  - Chunk cuts mid-word/sentence; HTML stripping is regex-based (visible hidden text and entities other than `&nbsp;`/`&amp;` remain), so document content flows into the model prompt as-is.
  - `role` is a plain command field; the agent tool and the assistant pass `customer` explicitly, which keeps `internal` docs out, but any new caller passing `operator` exposes them.
  - `embedTexts` caches by text but a failed batch mid-way aborts the whole call; the OpenAI error path is not translated beyond `MissingOpenAIKeyError`.
  - `restoreIndex` throws when the model differs; the seed does not catch it.
  - Known limit: `lexicalSearch` ORs every query word, so common words match almost every chunk, and it loads every match before the use case filters by audience and validity in JS. Fine for a few hundred chunks; moving those filters into the SQL with a `LIMIT` would bound it.

### Testing Requirements

- `npm test`: `domain/{retrieval,chunker,lexical-query}.test.ts` (unit), `application/use-cases/{search-documents,ingest-documents}.test.ts` (`search-documents` has a `makeSearchDocuments` suite with stub ports — semantic, unavailable embedder → lexical without embedding, `fallsBackOn` → lexical — plus the `searchDocuments` and `searchDocuments retrieval mode` suites: lexical under claude-cli with the same visibility and validity rules and without the model check, the `auto` quota fallback, forced openai rethrowing, incompatible dimensions), `infrastructure/{cached-openai-embedder,sqlite-chunk-store,sqlite-lexical-index,fixture-document-catalog}.test.ts` (the manifest: 80 unique docs, an internal doc exists, some with `validTo`, each readable and >1000 chars), `entry-points/{legacy,tools/search-documents.tool}.test.ts`; the seeded index (>300 chunks, all 1536-dim, reproducible across `seedApp()`); `/api/search` returns 503 `missing_openai_api_key` with a "restart" hint when the key is blank. Real embedding calls are not tested; re-running `ingest` needs `OPENAI_API_KEY`. `saveInitialIndex` is not tested (it rewrites `fixtures/`).

### Common Patterns

- Float32 BLOB round-trip via `vectorBuffer`/`readVector`; named-column `INSERT OR REPLACE` for cache and meta.
- Pure functions for chunking, visibility and ranking; side effects confined to the adapters. Paths are relative to the process cwd (`path.resolve('fixtures/...')`).
- Index and model mismatches stay plain `Error`s (a generic 500 over HTTP, the message as a tool error); only "Document not found." is a `DomainError`.
