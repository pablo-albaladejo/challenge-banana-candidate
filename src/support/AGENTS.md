# support

## Purpose

Human support: the support cases (incidents) opened by customers or by the agent's `request_human` tool, the operator's case list and dashboard workspace, and the operator's case view that explains a case with its conversation, agent events, transfers and the bank's record.

Hexagonal vertical (plan §10, 7d.3): `domain/` (pure rules), `application/` (ports, use cases; no services), `infrastructure/` (SQLite, telemetry and bank adapters), `entry-points/` (wiring, http, tools). No `legacy.ts`: no frozen path reaches this feature. Nothing else lives at the root but `index.ts` and this file.

## For AI Agents

### Working In This Directory

- `operatorId` must come from `actor()`. The operator is checked twice: on the session role in the handler, and on the person behind `actor.id` in `GetCaseDetail` (`requireOperator`). Both gates, the case's customer, the bank call signed as the operator, the operation filter, the tool's check order, the case owner (`ctx.userId`) and the one-open-case dedupe are pinned by mutation.
- Rank 2: value-imports only `identity`, `conversations` (rank 0) and `transfers` (rank 1), through their indexes and only in `entry-points/dependencies.ts`; `assistant` only as `import type { Tool }`.
- Lint (`eslint.config.mjs`): support is a layered vertical, so `index.ts` re-exports only `./entry-points/` (types allowed) and `src/server/` reaches it only through the index; `seed.ts` may also import its `infrastructure/`.
- Things worth scrutinizing:
  - `GetCaseDetail` reconciles through `transfers().getConversationTransfers({ userId: incident.user_id, … })`, which signs the bank call as the customer.
  - `incident` is returned whole; no scoping beyond the role check (every operator sees every case).
  - Part 2 (the verified case brief, "Send and close") lands here as new use cases over these ports; nothing writes `closed` yet.
